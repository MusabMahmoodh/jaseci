- **Fix: a scaled-to-zero app wakes in about half the time and no longer times out through the gateway**: a request to an HTTP-activated app waited about 30 s for its pod, and through the gateway it failed with `GATEWAY_TIMEOUT` before the pod was Ready. Most of the boot was one import: byllm and jac-scale's LLM telemetry both imported litellm at startup, 8 to 9 s in every pod, including services that never call a model. byllm now loads litellm and openai on first use, and the telemetry logger attaches when litellm loads. Pods also start faster: the startup probe checks every second, `readiness_initial_delay` defaults to 0, the shipped toolchain is not unpacked when the image already carries the same jac binary, the bundle unpacks inside `jac-bootstrap` instead of a separate init container, and `wait_image` defaults to `busybox:1.36` so kubelet stops re-pulling `latest`. An HTTP-activated app without an explicit `http_forward_timeout` or `rpc_timeout` now waits at least 300 s, so a cold request is served instead of timing out.
